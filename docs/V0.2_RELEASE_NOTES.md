## What shipped

### Backend — modular monolith, single FastAPI process

| Capability | What it does |
|---|---|
| Product catalog | Products with MRP / sale price / offer window, brand, SKU, category tree, tags, specs, media, featured flag. pg_trgm search across name/brand/SKU with price & category filters and sort (newest, discount, price asc/desc). Effective pricing applies offer window + sale price at read time. |
| Inventory | `on_hand − reserved` model. Atomic `UPDATE … WHERE on_hand − reserved >= :qty` to prevent oversell under concurrent checkouts. Stock movements audited on every change. Admin stock adjust (set/delta/restock/damage/return) with threshold edits and full movement history per product. |
| Carts | Guest carts with session token, real stock validation, IDOR ownership guards, guest→user merge on login (conflicts resolved in favour of the user's active cart). |
| Checkout | Server-side pricing — cart snapshot with effective prices, coupon redemption computed atomically in the same transaction as stock reservation, address snapshot on the order, outbox events for notifications. Two payment modes: COD (confirmed immediately) and ONLINE (pending until capture). |
| Payments | Provider-agnostic `BasePaymentProvider` with a real `CashfreeProvider` (live `httpx` calls to Cashfree API). Amount always validated against the order total server-side — client values are ignored. Cashfree Web Checkout: server creates order → returns `payment_session_id` → frontend loads Cashfree JS SDK → `Cashfree.checkout({paymentSessionId, redirectTarget})`. Client verify calls Cashfree API to confirm payment status (not signature-based). Webhook: HMAC-SHA256 signature verification + Redis `SETNX` per event id for idempotent dedup. Capture/restock/refund wired through the Cashfree provider API when keys are configured. Refund requires the Cashfree order ID (cf_order_id). When the provider rejects (bad keys, outage), `payments/initiate` returns `503` — not a raw 500. |
| Coupons | Validate endpoint (free, rate-limited) returns applicability + discount before checkout. Atomic `UPDATE … SET usage_count = usage_count + 1 WHERE … AND (usage_limit IS NULL OR usage_count < usage_limit)` inside checkout, so a 1-use coupon can only be redeemed by one buyer under concurrency. |
| Addresses | CRUD with default-address semantics and India pincode validation (6-digit). |
| Wishlist | Add/remove/list with raw `INSERT … ON CONFLICT DO NOTHING` to avoid asyncpg greenlet issues; legacy JSON import path for migration. |
| Notifications | Transactional email via Resend (`transactional@appname.com` sender), in-app notification centre, outbox pattern — events are written inside DB transactions and dispatched by the ARQ worker (cron every minute, `FOR UPDATE SKIP LOCKED`, retries, per-event retry cap, dead-letter table). |
| Newsletter | Capture subscribe/unsubscribe with idempotent dedup; no duplicate emails for double-submit. |
| Admin | Dashboard (today's orders/revenue, 14-day revenue trend, recent orders, top products by revenue over 30 days), customer list, coupon manager, store settings (COD toggle, free-shipping threshold, banner text/URL), inventory manager, order manager with status transitions (CONFIRMED → PROCESSING → SHIPPED → DELIVERED) and tracking. All endpoints require staff auth; owners see only their shop. |
| Media | Staff-only R2 presigned upload (`POST /api/v1/media/presign`) returning a short-lived PUT URL and the public `media.elektrix.in` CDN URL. File extension + content-type validated; 10 MB cap; images only. |
| Auth | Register, login, refresh-token rotation with replay detection, password reset (email + outbox event), password change (current-password verification), change-email with verification. Rate-limited: login 10/min, register 5/5min. |
| Rate limiting | Redis fixed-window middleware on sensitive endpoints (login, register, checkout, coupon validate, newsletter, store product search). Skipped in test env. |
| Health | `/health/live`, `/health/ready`, `/health/diagnostics` + `/api/v1/system/status` — truthful diagnostics: real DB/Redis latency, migration version, git commit, provider status, disk. |
| RLS | Multi-tenant schema with row-level security per business. `app.business_id` and `app.role` GUCs set per request. Staff helper `elektrix_is_staff()`. Users SELECT scoped to their own basic profile for non-staff. |

### Storefront — root Next.js app on `elektrix.in`

- Catalog listing, category filter, search, price filters, sort. Effective pricing shown (sale price + GST-inclusive).
- Product detail: media gallery, specs, variants, related products, recently viewed strip.
- Cart drawer with guest→user merge indicator, stock rejection, quantity stepper.
- Checkout stepper: address → offers → payment. COD and Cashfree Web Checkout (live client id from `.env`). Payment cancelled → order stays PENDING, retry available. 503 from the provider surfaces as a retryable toast. When online payment is unavailable, the UI suggests Cash on Delivery.
- Wishlist page, compare page (spec-based feature comparison), notifications bell with in-app centre.
- Account: orders (with tracking link), addresses, wishlist.
- Order tracking page by order number.
- SEO: `robots.txt`, `sitemap.xml` (products + blog), per-product metadata, `Product` JSON-LD.
- `next/image` configured for Unsplash + GitHub raw.

### Admin — `apps/web` on `admin.elektrix.in`

- Dashboard with real metrics (GitHub Avatar for admin user, order/revenue counts, 14-day sparkline, recent orders, top products).
- Products: list with status/featured/stock badges, create (all fields, variants, offer scheduling, R2 image upload), edit (with full field editing, offer window, media).
- Inventory: paginated table, search by name/SKU, low/out-of-stock filters, adjust modal (set/delta/restock/damage/return + threshold edit), movement history drawer.
- Orders: list with filters, detail with status transition guards, tracking display, note.
- Coupons: list/create/edit (code, type, value, usage limit, min order, per-customer limit).
- Settings: COD toggle, free-shipping threshold, banner text/url.
- Customers: list + detail.
- AuthGuard on all dashboard routes.

### Infrastructure

- `Dockerfile.storefront` — standalone Next.js runtime image, multi-stage, `NEXT_PUBLIC_API_URL` build arg.
- `compose.prod.vm1.yaml` — 2× API, 2× storefront (:3000), 2× admin (:3100), 1× workers, Redis. Nginx at the edge. CI builds all four images; deploy script runs `build → pg_dump → migrate → RLS → certs → rollout → seed → smoke → nginx reload`.
- Nginx: 4 vhosts (elektrix.in + www redirect, admin.elektrix.in noindex/DENY frame, api.elektrix.in no-cache/rate-limited). CSP allows Cashfree SDK + checkout domains. Gzip, static-asset caching, security headers. Storefront and admin also served via Vercel with CSP headers in `vercel.json`.
- CI/CD: `backend-tests` job runs `scripts/run_backend_tests.sh` (boot scratch PG + Redis, drop schema, migrate, seed, pytest). `deploy-vps.yml` triggers on `workflow_run` gated on CI success.

## Pre-launch fixes applied

- `::jsonb` cast syntax error in Alembic asyncpg → `CAST(:var AS jsonb)`.
- Category filter only matched exact slug → added parent subquery so products under child categories show.
- `product_media` had no `created_at` → removed from ORDER BY in storefront catalog.
- Wishlist `MissingGreenlet` → raw SQL `INSERT … ON CONFLICT DO NOTHING`.
- Address duplicate `is_default` kwarg → extract from `model_dump` first.
- Newsletter INSERT..RETURNING blocked by staff-only RLS → relaxed to `USING (true)`.
- Users UPDATE blocked by RLS → `_bind_rls_owner(user_id)` sets `app.user_id` GUC.
- Webhook session couldn't update orders under RLS → `app.role = 'platform_admin'` set in webhook session.
- Trailing-slash 307 redirects on `/api/v1/orders/` etc → removed trailing slashes from route declarations.
- Hardcoded Supabase credential in `apply_rls.py` removed (rotate advised — leaked in git history).
- Storefront `next.config.ts` missing `output: "standalone"` → added (Docker build needs it).
- Nginx bind-mount file inode stale after git checkout → documented; force-recreate `nginx` container after any `git checkout` that touches `infra/nginx/nginx.conf`.

## What did NOT ship (and why)

- **Sell marketplace (`sell.elektrix.in`):** explicitly out of scope for v0.2.
- **HTTP-only cookie auth:** Bearer + localStorage kept for v0.2; cookie migration is v0.3.
- **Real Razorpay keys:** the production `.env` carries `RAZORPAY_KEY_ID=rzp_live_yourlivekey` (placeholder) + `RESEND_API_KEY`. The app is wired for live keys — only the key id needs to be replaced before real payments work. Until then, ONLINE checkout initiates return `503` (truthful, retryable) and COD is the only completed payment path. The Resend key is real and transactional email is live.

## DNS

Four domains must point at the VPS (`161.118.254.169`). Only `api.elektrix.in` is live (cert issued). The other three hit self-signed placeholders until DNS is updated — the app already works behind them once certs are in place.

| Domain | Record | Value | Cert status |
|---|---|---|---|
| `api.elektrix.in` | A | `161.118.254.169` | ✅ Let's Encrypt (expires 2026-11-15) |
| `elektrix.in` | A | `161.118.254.169` | ❌ placeholder — CNAME/proxy issue; re-run `bash infra/scripts/setup_ssl.sh` after DNS |
| `www.elektrix.in` | A | `161.118.254.169` | ❌ placeholder — same |
| `admin.elektrix.in` | A | `161.118.254.169` | ❌ placeholder — NXDOMAIN; add A record first |

For Cloudflare: set `elektrix.in`, `www.elektrix.in`, `admin.elektrix.in` A records (orange-cloud OFF for `admin.elektrix.in` and `api.elektrix.in` if you want direct origin TLS; orange-cloud ON is fine for the storefront if the SSL/TLS mode is set to Full (strict)). Then run `bash infra/scripts/setup_ssl.sh`.

## Rollback

Migrations are additive-only with a rehearsed downgrade path. The deploy script backs up the DB before migrating (`backups/pre_deploy_*.dump`). On smoke failure it rolls back the git commit and re-runs the compose stack but does **not** revert the DB — see `docs/ROLLBACK.md`. A full DB restore: `pg_restore -d $DATABASE_URL backups/pre_deploy_20260817_142227.dump`.
